# ADR-0005: イベントの開催日を JST のローカル値で保存する

- status: 承認済み
- 日付: 2026-08-28

## 背景

CLAUDE.md には当初「**DB には UTC で保存し、表示時に変換する**」と
一律の方針を書いていた。データモデルを設計する段階で、
これをイベントの開催日に適用すると破綻することがわかった。

## 決定

保存形式を用途で 2 種類に分ける。

| 種類 | 型 | 扱い |
| --- | --- | --- |
| システムの時刻（作成日時・取り込み日時） | `TIMESTAMPTZ` | **UTC で保存**し、表示時に JST へ変換 |
| イベントの開催日・出演時刻 | `DATE` / `TIME` | **JST のローカル値で保存**し、UTC に変換しない |

## 理由

「8 月 30 日の出演」という情報は、特定の瞬間ではなく**暦日そのもの**を指す。
これを `TIMESTAMPTZ` に変換すると

```
2026-08-30T00:00+09:00  =  2026-08-29T15:00Z
```

となり、UTC で日付を取り出すと 8 月 29 日になる。
この状態で月境界のクエリを書くと、**月初・月末の出演情報が隣の月へ紛れ込む**。

誕生日や祝日を UTC で保存しないのと同じ理由である。

## 検討した代替案

| 案 | 却下理由 |
| --- | --- |
| すべて `TIMESTAMPTZ` に統一する | 上記のとおり月境界がずれる |
| `DATE` と `TIMESTAMPTZ` を併用する | 冗長で、どちらが正か曖昧になる |

## 結果

- 月次クエリが `WHERE appearance_date BETWEEN ? AND ?` で書ける
- サーバやコンテナの `TZ` 設定に結果が依存しない
- 出演時刻が `NULL` でも日付が確定する（タイムテーブル未発表を表現できる）
- **API もオフセットを付けずに返す**（`"2026-09-16"` / `"19:50:00"`）。
  付けるとクライアント側の変換で日付がずれる
- CLAUDE.md の一律 UTC 方針を修正した
