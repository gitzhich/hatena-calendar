# ADR-0004: 自動取り込みは新規追加と空欄補完のみとする

- status: 承認済み
- 日付: 2026-08-28

## 背景

実際の告知を調べたところ、公式は 1 つのイベントについて
**複数回に分けて告知する**ことがわかった。

```
① 「XINXIN東京公演情報解禁」    → 日付・会場・イベント名・チケット（出演時刻はまだ無い）
② 「XINXIN千葉公演タイムテーブル解禁」→ 出演時刻を後から告知
```

②を取り込むとき、①で作った行をどう扱うかを決める必要があった。

## 決定

**既存行の値が `NULL` の列だけを埋める。値が入っている列は上書きしない。**

## 理由

- 全面上書きにすると、**管理者が手で直した内容が次の取り込みで巻き戻る**。
  運用が成立しない
- 常に新規行を作ると、同じイベントが二重登録される。
  カレンダーに同じ公演が 2 つ並ぶ

## 検討した代替案

| 案 | 却下理由 |
| --- | --- |
| 常に新規行を作る | 二重登録される。管理者が毎回手で統合することになる |
| 全項目を上書きする | 手動修正が消える |

## 結果

- **日程変更・中止の告知は自動反映されない。** 既に値が入っているため。
  管理者が手で修正または削除する（FR-22, FR-23）
- 同一イベントの判定キーが必要になった（[ADR-0006](0006-event-key-separation.md)）
- 補完が起きたとき、出典 URL も新しい告知のものへ更新する。
  出演時刻を載せた告知が出典として示されるべきで、
  時刻の書かれていない最初の告知を指し続けるのは不正確
- 投稿は**古い順に処理する**必要がある。①→②の順で反映しないと補完が働かない
