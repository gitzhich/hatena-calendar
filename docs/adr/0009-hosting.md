# ADR-0009: ホスティングを Vercel + Fly.io + Neon にする

- status: 承認済み
- 日付: 2026-08-28

## 背景

個人開発としてコストを抑えつつ、要件を満たすホスティング構成を選ぶ必要があった。
無料枠のあるプラットフォームは多いが、**スリープする**ものが大半である。

## 決定

| 層 | ホスティング | 月額 |
| --- | --- | --- |
| Next.js | Vercel（Hobby） | $0 |
| Spring Boot | **Fly.io（常時起動）** | $2〜5 |
| PostgreSQL | Neon（Free） | $0 |

## 理由

**バックエンドを常時起動にする必要がある。**

- 取り込みを Spring Boot の `@Scheduled` で動かすため、
  **スリープするとポーリングが止まる**
- JVM のコールドスタートは 5〜15 秒。スリープからの復帰は 30〜60 秒かかり、
  NFR-01（サーバ応答 p95 300ms）を満たせない

**DB に Neon を選んだ理由。**

- バックアップとバージョン管理が自動。個人運用で最も現実的な事故は
  「バックアップを設定し忘れたままのデータ消失」であり、これを避ける
- ストレージ 0.5GB に対し、本アプリの増加量は**年間約 4MB**で余裕がある

## 検討した代替案

| 案 | 却下理由 |
| --- | --- |
| Render 無料枠 | 15 分でスリープし `@Scheduled` が止まる |
| Cloud Run | スケールトゥゼロのため Cloud Scheduler が別途必要。GCP の設定が増える |
| 単一 VPS + Docker Compose | OS 更新・TLS 証明書・バックアップの自己管理がセキュリティ方針と衝突する |
| Fly Managed Postgres | $38/月。今回の規模には過剰 |
| Fly Postgres（非マネージド） | $2/月と安いが**バックアップを自分で組む**必要がある |
| Supabase | 1 週間の非アクティブでプロジェクトが一時停止する |

## 結果

- 月額の見込みは **$4〜7**（X API 込み）
- **Neon の制約はストレージではなくコンピュート時間**（100 CU-hours/月）。
  閲覧アクセスで超えうるため、ISR キャッシュで DB まで届かせない設計にした
- 無料枠の上限に達すると**自動課金ではなくコンピュートが停止する**。
  サイトが閲覧不能になるため、消費量の監視を運用項目に入れた
- Fly.io のインスタンスは **1 台に固定**する。複数台だと取り込みが多重起動する
