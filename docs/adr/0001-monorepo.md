# ADR-0001: モノレポ構成を採用する

- status: 承認済み
- 日付: 2026-08-28

## 背景

フロントエンドに Next.js、バックエンドに Spring Boot を使い、
将来 Expo (EAS) でモバイルアプリを追加する予定がある。
リポジトリを分けるか 1 つにまとめるかを決める必要があった。

## 決定

**1 つのリポジトリに `frontend/` `backend/` `docs/`（将来 `mobile/`）を並べる。**

## 理由

- API 契約の変更とその実装が**同じコミットに入る**。フロントとバックエンドで
  契約がずれた状態がリポジトリに残らない
- 設計文書を 1 か所に置ける。要件・データモデル・API がリポジトリ間で
  同期ずれを起こさない
- EAS を追加するとき、既存の API 設計をそのまま参照できる

## 検討した代替案

**リポジトリを分離する。** デプロイ単位が明確に分かれる利点はあるが、
設計文書と型定義の同期を自前で運用する必要がある。
個人開発でその運用コストを払う理由がない。

## 結果

- デプロイ設定は各サブディレクトリに置き、Vercel と Fly.io の双方で
  ルートディレクトリを指定する必要がある
- CI を組む際、変更されたディレクトリだけをビルドする工夫が要る
