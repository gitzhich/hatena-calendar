# ADR-0020: 1 回の取り込みを 1,000 件で頭打ちにし、超過分は取得を諦める

- status: 承認済み
- 日付: 2026-09-03

## 背景

取り込みは 1 回の実行で取るページ数に上限を設けている（既定 10 ページ = 最大 1,000 件）。
暴走した課金を防ぐためである（[x-integration.md](../x-integration.md) 第 3.4 節）。

**上限に達したときの取得位置の扱いが決まっていなかった。**
第 3.4 節は「次回の実行に持ち越す」と書き、第 2.1 節は
「`last_fetched_tweet_id` は取得できた最大 ID で更新する」と書いている。
実装は後者に従っている。

`GET /2/users/{id}/tweets` は**新しい順**に返し、`next_token` は**より古い**ページへ進む。
上限で打ち切ったとき未取得なのは古い側なので、最大 ID まで位置を進めると
**その区間は `since_id` の外に落ちて二度と取得されない**。
1 回の実行で 1,000 件を超えて滞留したときにだけ起き、ログにも残らなかった。

## 決定

**上限に達したら、未取得の古い側は取得を諦める。取得位置は取得できた最大 ID へ進める。**
バックフィル（`start_time` 指定）でも同じ規則にする。

**打ち切ったことを `ingestion_run.truncated` に記録し、管理画面に警告として出す。**

## 理由

「持ち越す」（＝位置を進めない）を採ると**位置が永久に進まない**。
滞留が 1,000 件を超えている限り、次回も同じ最新 1,000 件を取って再び打ち切る。
X API の 24 時間の重複排除は UTC の日跨ぎで切れるため、
**$5/日 が上限なく積み上がる**。取りこぼしを避けようとして、より重い障害を作る。

進める（諦める）なら:

- 1 回の実行の課金が **1,000 × $0.005 = $5 で頭打ち**になる
- 次回は必ず前進するので、滞留は 1 回で解消する
- 失う投稿は古い側に限られる

失うことそのものは、既に受け入れている性質と同じである。
タイムラインは約 3,200 件までしか遡れず、
**過去分の完全な取り込みは要件の非スコープ**としている
（[requirements.md](../requirements.md) 第 9 章、[x-integration.md](../x-integration.md) 第 8 章）。
新しい妥協を持ち込むのではなく、既にある限界の延長として扱う。

**ただし黙って起きてはいけない。** 諦めたことを知らなければ、
管理者は手動登録で補う判断ができない。`log.warn` は Fly のログを見に行かないと
読めないため、実行の記録に残して管理画面に出す（NFR-09）。

## 検討した代替案

| 案 | 却下理由 |
| --- | --- |
| 打ち切った実行では位置を更新しない | 位置が永久に進まず、日跨ぎで再課金が積み上がる（上記） |
| 取得できた最小 ID の 1 つ手前まで進める | `since_id` は下限なので、未取得の古い区間をまるごと飛ばす。取りこぼしは同じで、位置だけが不正確になる |
| `until_id` で持ち越し、次回に続きを取る | 取りこぼしは無くせるが、`source_account` に持ち越し用の列が要り、次の実行（30 分後）まで滞留が解消しない。1 回で取り切りたいという運用の要求と合わない |
| ページ上限を 32（API の遡り上限 3,200 件）へ上げる | 1 回の課金が最大 $16 になり、NFR-04 の月 $5 と釣り合わない |
| `status` に `TRUNCATED` を足す | 連続失敗の判定（`IngestionHaltRule`）が `status` を見ている。値を増やすと打ち切りの判定まで巻き込む。取りこぼしは失敗ではない |

## 結果

- 1,000 件を超える滞留が起きた場合、**古い側の投稿は手動登録で補う**運用になる
- 実測では 3 か月分のバックフィルが 338 件だったため、通常運用で上限に届かない
  （[requirements.md](../requirements.md) 第 11 章）
- `ingestion_run` に列が 1 つ増えた（`V2__ingestion_run_truncated.sql`）
- 取りこぼしの起きた実行を後から SQL で特定できる
  （`SELECT * FROM ingestion_run WHERE truncated`）
