# ADR-0003: 取り込み結果に承認フローを設けない

- status: 承認済み
- 日付: 2026-08-28

## 背景

X から抽出した出演情報を、そのまま公開するか、管理者の承認を経て公開するか。

**当初は承認フローを設ける方針だった。**「誤った日時を公開するほうが、
表示されないより害が大きい」という判断で、抽出結果を「取り込み候補」として
保留し、管理者が承認したものだけを公開する設計にしていた。

## 決定

**承認フローを設けない。抽出に成功した出演情報はそのまま公開する。**

## 理由

- 承認を挟むと、**管理者が作業するまで情報が公開されない**。
  出演情報は告知から公演までの期間が短いこともあり、速報性が失われる
- ファンにとって「情報がまだ出ていない」ことのコストが高い。
  カレンダーを見ても空なら、結局 X を遡ることになりアプリの目的を果たさない
- 誤りは事後修正で対応できる。そのかわり**抽出精度を高めることに投資する**

## 検討した代替案

| 案 | 却下理由 |
| --- | --- |
| 全件を承認制にする | 速報性が失われる（上記） |
| 信頼度による部分承認 | 信頼度の閾値調整が必要で、実装と運用が複雑になる |

## 結果

- **抽出精度が公開情報の品質を直接決める**。実サンプルに対する抽出テストが必須
- 管理者は公開後の**事後点検**を行う（FR-24）。承認ではなく点検
- 誤情報のリスクは、免責表示（FR-07）と出典リンク（FR-06）で緩和する。
  閲覧者が公式 X で裏を取れる状態を保つ
- データモデルから「取り込み候補」の概念が消え、
  出演情報は行が存在すること自体が公開を意味するようになった
- 情報源アカウントが乗っ取られた場合、偽情報が自動公開される
  （[docs/security.md](../security.md) T-05）。検知と復旧で対応する
