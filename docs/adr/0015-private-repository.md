# ADR-0015: リポジトリを外部公開しない

- status: 承認済み
- 日付: 2026-09-01

## 背景

`docs/x-post-sample/` には XINXIN 公式アカウントの投稿本文をそのまま置いている
（実サンプル 13 件）。抽出ルールはすべてこの実データから導出され、
第 5.11 節の期待値と第 9 章のテストもここに依存している。

一方で [security.md](../security.md) T-07 は、これを
「公開すると転載にあたる。`.gitignore` へ移すか、架空のデータに差し替える」としていた。
つまり**サンプルを保持し続けることと、リポジトリを公開することが両立しない**状態だった。

サンプルはレビューのたびに増える運用でもある
（[security.md](../security.md) 第 6.3 節: 抽出ミスがあれば投稿を追加してテストを増やす）。
先送りするほど選択肢が狭まるため、実装前に決着させる必要があった。

## 決定

**リポジトリを外部公開しない。** 公開範囲は運用者本人に限る。
`docs/x-post-sample/` は投稿本文のまま保持する。

## 理由

- **架空データでは抽出テストの意味が薄れる。** 実サンプルの価値は、
  半角カナ（`ﾆｷﾌﾟﾚ`）、3 種類の括弧、曜日の誤記、`RAD HALL` と `RADHALL` の揺れ、
  同日 2 枠、住所行の混入といった**実際にしか現れない崩れ方**にある。
  架空データを書き起こすと、想定できた崩れ方しかテストできない
- **公開する動機がない。** ファンが個人で運用する非公式ツールであり、
  外部の貢献者を受け入れる想定もない。公開の利点が
  「実データでテストできなくなる」という損失に見合わない
- **LR-02 の趣旨には反しない。** LR-02（投稿本文を転載せず事実データに正規化して保持）は
  **公開されるアプリ**に対する要件であり、非公開リポジトリ内の開発用フィクスチャは
  その対象ではない。アプリ側の受入基準
  （DB に本文の列がない／画面に本文を出さない）は何も変わらない

## 検討した代替案

| 案 | 却下理由 |
| --- | --- |
| サンプルを架空データに差し替えて公開する | 実際の表記ゆれを再現できず、抽出テストの検証力が落ちる。承認フローを持たない設計（[ADR-0003](0003-no-approval-flow.md)）では抽出精度が公開情報の品質を直接決めるため、テストの劣化がそのまま誤情報のリスクになる |
| サンプルを `.gitignore` へ移して公開する | 既にコミット済みの分は履歴に残るため、公開した時点で転載になる。加えて、テストデータがリポジトリに無いと CI で抽出テストを回せない |
| サンプルを別の非公開リポジトリへ分離し、本体だけ公開する | モノレポの利点（[ADR-0001](0001-monorepo.md)）を削る。テストデータと抽出ルールが別リポジトリに分かれ、同期ずれを自前で運用することになる |

## 結果

- **この決定は実質的に不可逆。** サンプルを追加するたびコミット履歴に本文が積み上がる。
  後から公開へ転じるには、架空データへの差し替えに加えて**履歴からの除去**が要る
- リポジトリのホスティング先アカウントが侵害されればサンプルは流出する。
  ただし内容は公式アカウントが公開済みの投稿であり、被害は限定的
- **シークレットをコミットしない方針は変わらない**（[security.md](../security.md) T-01）。
  非公開は多層防御の 1 枚であって、コミットしてよい理由にはならない
- T-07 の位置づけが「公開時に確認すること」から
  「非公開を維持すること、および転じる場合の手順」に変わった
