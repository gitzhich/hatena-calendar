# ADR-0012: 同じ日・同じイベントの複数出演枠を別の行として持つ

- status: 承認済み
- 日付: 2026-08-29

## 背景

[ADR-0006](0006-event-key-separation.md) で `UNIQUE (appearance_date, event_key)` を
張ると決めた。これは「1 日 1 イベントにつき出演は 1 回」という暗黙の前提に立っている。

実サンプル 6.txt でこの前提が崩れた。1 つのサーキットイベントの中で、
XINXIN が同じ日に 2 つの会場へ出演している。

```
8/25(火) 『DERAX JAM~ DERA MAXIMUM JAM ~』
  📍NAGOYA ReNY limited  🎤16:35-17:05 XINXIN①
  📍RADHALL              🎤19:50-20:15 XINXIN②
```

`appearance_date` と `event_key` が両方一致するため、**2 公演目を登録できない**。
空欄補完（[data-model.md](../data-model.md) 第 7.1 節）に流れても、
1 公演目の出演時刻が既に埋まっているので上書きされず、2 公演目は失われる。
ファンにとっては「何時にどこで見られるか」が要件の中心（FR-03 / FR-04）であり、
落としてよい情報ではない。

## 決定

一意性のキーに**出演開始時刻を加える**。

```sql
CONSTRAINT appearance_unique_event
    UNIQUE NULLS NOT DISTINCT
        (appearance_date, event_key, performance_start_time)
```

出演枠ごとに `appearance` を 1 行ずつ作る。会場も枠ごとに持つ。

## 理由

- **枠を区別する値のうち、最も確実に取れるのが開始時刻。** 会場は告知に
  書かれないことがあり（タイムテーブル未発表の段階）、後から補完される列でもある。
  開始時刻は出演枠そのものの識別子として機能する
- **`NULLS NOT DISTINCT` が必要。** PostgreSQL の `UNIQUE` は既定で `NULL` 同士を
  「異なる値」として扱う。これを付けないと、タイムテーブル未発表の告知
  （実サンプル 1.txt）から作られる時刻 `NULL` の行が何行でも作れてしまい、
  再処理のたびに重複する。付けることで「時刻未定の行は 1 日 1 イベントにつき 1 行」を
  DB 側で保証できる
- ADR-0006 の趣旨（**アプリの照合ロジックと DB の制約を同じキーで判定する**）は
  そのまま保たれる。キーが 2 列から 3 列になっただけである

## 検討した代替案

| 案 | 却下理由 |
| --- | --- |
| 会場を含める `(date, event_key, venue_name)` | 6.txt は会場が違うので通るが、同じ会場での昼夜 2 公演を区別できない。会場は後から補完される列でもあり、補完によって一意キーが変わる |
| `UNIQUE` を外してアプリ側だけで照合する | DB による保証が失われる。ADR-0006 で明示的に却下した構成に戻ることになる |
| 出演枠を 1 行にまとめ、時刻を複数持つ | 時刻の配列や別テーブルが必要になり、MVP の軽さを損なう。カレンダー表示でも結局は枠ごとに展開する |
| 標準の `UNIQUE`（`NULLS DISTINCT`）にする | 時刻 `NULL` の行の重複を DB で防げない。補完ロジックが先に効くので実害は小さいが、保証を持てるならそちらを取る |

## 結果

- 空欄補完の照合を段階化した（[data-model.md](../data-model.md) 第 7.1 節）。
  まず 3 列の完全一致を探し、なければ同じ日・同じイベントで時刻が `NULL` の行を探し、
  それもなければ新規登録する
- 同じ日・同じイベントに 2 枠が届いた場合、先に処理した枠が既存の時刻なし行を引き継ぎ、
  もう一方が新規行になる。**どちらが引き継ぐかは処理順に依存する**が、
  最終的な行数と内容は変わらない
- 管理 API の `409` 条件も 3 列になった（[api.md](../api.md) 第 5.2 節）
- **PostgreSQL 15 以降に依存する。** Neon が提供するのは 16 / 17 系なので問題ない
- 公開 API では、同じ日に同じ `eventName` が複数並びうる。
  会場と開始時刻で区別する（FR-03）

## 更新履歴

- 2026-09-01: `NULLS NOT DISTINCT` の理由で挙げた「タイムテーブル未発表の告知
  （実サンプル 1.txt）から時刻 `NULL` の行が作られる」は、抽出対象の絞り込みにより
  自動取り込みでは起きなくなった。時刻 `NULL` の行は**管理者の手動登録**から生まれる
  （[x-integration.md](../x-integration.md) 第 5.2 節）。
  制約が必要である結論は変わらないため決定内容は変更しない
